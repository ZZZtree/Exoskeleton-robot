# 多用户网关：功能定位与并发实测（2026-10-16）

> 回答一个定位问题：**"多用户对话网关"是我们的亮点吗？**
> 答：是**功能亮点**，不是**性能亮点**。下面是实测依据。

## 一、机制（确实做了什么）

| 机制 | 实现 | 配置 |
|---|---|---|
| 多用户会话隔离 | 每 user 独立 history + 独立 slot 映射 | `MAX_SESSIONS=10` |
| 并发调度 | `threading.Semaphore(16)` 匹配 16 slots | 超出排队不丢弃 |
| 上下文溢出归档 | 超 90% 窗口 → 完整历史 gzip 存盘 + 裁剪 | `CTX_SAFETY=0.9` |
| 磁盘 swap 换入 | LRU 内存 + 磁盘恢复 + 环形容量管理 | 512MB 环形 |
| 语义检索换入 | bge-small-zh RAG，把相关历史换进窗口 | 预算 40% |
| 缓存表 | mem/disk 索引 + 命中率统计 | `/stats` 暴露 |
| 零第三方依赖 | `ThreadingHTTPServer` + 标准库 | 纯 Python |

## 二、并发实测（★ 关键数据）

条件：9B / 64K 池 / 16-slot unified，每用户连续 3 轮，max_tokens=48。
脚本：`tools/concurrency_test.py`，原始数据：`docs/concurrency_measured_20261016.txt`

| 并发 | 总墙钟 | 成功 | 吞吐(req/s) | TTFT 中位 | TTFT P95 | 端到端中位 |
|---|---|---|---|---|---|---|
| 1 | 12.1s | 3/3 | 0.25 | 560ms | 7067ms | 2.00s |
| 4 | 16.1s | 12/12 | **0.74** | 982ms | 1916ms | 4.69s |
| 8 | 33.7s | 24/24 | 0.71 | 2077ms | 5808ms | 10.32s |
| 16 | 38.2s | 48/48 | **1.26** | 1690ms | 9216ms | 11.78s |
| 32 | 72.1s | **96/96** | **1.33** | 12239ms | 20412ms | 21.76s |

### 三条硬结论

1. **稳定性 ✅**：1→32 并发，**96/96 零失败**（32 并发下 16 个排队也不丢请求）
2. **吞吐封顶 ⚠️**：C=16→32 吞吐几乎不变（1.26→1.33 req/s）
   → **瓶颈是 GPU 算力**（9B 单请求 22 tok/s），**不是 slot 数**
   → **16 slot 是"容纳能力"（不排队），不是"吞吐能力"（不加速）**
3. **延迟随并发上升 ⚠️**：TTFT 中位 560ms(C=1) → 12.2s(C=32)，**21 倍**
   → 并发本质是 **GPU 时间片共享**：并发越高，每个人越慢

### 网关层的延时代价（诚实说明）

| 路径 | 单请求 TTFT |
|---|---|
| 直连引擎（`:8080`）| ~210ms |
| 经网关（`:8000`）| ~560ms |

→ 网关带来 **+350ms** 开销，换来的是**多用户隔离 + 长对话记忆 + RAG 检索**。
（开销来自：HTTP 多一跳、会话构建、token 预算计算、可能的 RAG 检索）

## 三、定位结论

| 说法 | 判定 |
|---|---|
| "多用户对话网关" | ✅ 功能成立（隔离/并发/记忆/零失败）|
| "高并发推理服务" | ❌ 不成立（1.3 req/s 封顶，GPU 瓶颈）|
| "支持 16 用户同时在线" | ✅ 成立（容纳不排队）|
| "并发能提升吞吐" | ❌ 不成立（并发=时间片，越高越慢）|

**📌 正确的一句话定位：**
> "面向家庭场景（3-5 人偶发使用）的多用户对话网关：会话隔离 + 磁盘 swap 长对话记忆 + RAG 语义换入，
> 16 并发零失败；吞吐受 Jetson GPU 算力限制（~1.3 req/s），设计目标是**记忆与稳定性**而非高吞吐商业服务。"

**📌 真正的技术亮点排序**（按含金量）：
1. **长对话记忆管理**（100 轮快 10 倍 / 200 轮 10/10 抽查 / 500-token 窗口跑 200 轮）
2. **反直觉实验**：固定 slot 是负优化（动态 57.5% vs 固定 21.8% 命中率）
3. **小窗口 + 外部记忆架构**（swap + RAG 把"上下文不足"转为"外部检索"）
4. **多用户网关**（功能完整、工程扎实，但非性能亮点）
